# Tech Review Prompt

## 任务
作为 Evolution Engine 的 TECH_REVIEW 阶段，执行前端技术债务清理和代码健康度扫描。

## 输入
1. 读取 `.claude/evolution/state.json` 了解当前状态
2. 运行 `npm run lint` 获取 lint 警告
3. 运行 `npx tsc --noEmit` 获取类型错误
4. 扫描 `src/` 目录查找技术债务

## 扫描范围

### 1. 未使用导入
运行 ESLint no-unused-vars 规则，列出所有未使用的 imports 并删除

### 2. 重复代码
扫描 src/ 目录，识别：
- 完全相同的代码块（超过 5 行）
- 相似函数可以合并提取为共享函数
- 重复的 type/interface 定义

### 3. 复杂度超标
使用 ESLint complexity 规则，找出圈复杂度 > 10 的函数，考虑拆分

### 4. 过长函数
找出超过 50 行的函数，评估是否可以拆分

### 5. 缺失类型注解
找出 any 类型使用超过 5 次的文件，补充类型定义

### 6. 硬编码值
扫描常见的硬编码：
- magic numbers（如 `1000`、`86400000`）→ 提取为命名常量
- 重复的字符串字面量 → 提取为 const
- API URL、阈值、常量未抽取

### 7. 死代码
找出：
- 导出了但未被使用的函数/变量
- 注释掉的代码块
- 已废弃的 export

## 执行策略

**按优先级处理：**
1. **高优先级**：lint 错误、类型错误（必须修复）
2. **中优先级**：未使用导入、死代码、硬编码（清理）
3. **低优先级**：重复代码提取、函数拆分（可选）

## 输出要求

1. 列出发现的所有问题，按优先级分组
2. 对每个问题：说明位置、问题类型、建议修复方案
3. 修复后运行 `npm run build` 确保无回归
4. 更新 state.json 记录本次 tech-review 清理的内容
5. 完成后触发 BRAINSTORM 阶段

## 技术债务基线

记录本次扫描的基线数据：
- 总 lint warnings
- 总 type errors
- 未使用导入数
- any 类型使用数
- 超长函数数

作为下次 tech-review 的对比基准。

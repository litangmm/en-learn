# Evolution Engine 规则

## 进化模式

- **默认模式**：`vision`（围绕产品愿景进化）
- **探索模式**：每周五自动切换为 `exploration`（自由发散）
- **技术清理**：每完成 4 次功能进化后，下一次自动切换为 `tech-review`

## 头脑风暴规则

- 每次产出 3-5 个 Epic 方向
- 每个 Epic 需附带可拆分的 3-6 个迭代思路
- 必须包含：需求描述、提出者、支持者、反对意见、优先级、预估工作量
- PM 子角色互评时，反对意见必须附带理由

## 技术清理规则

- 扫描范围：未使用导入、重复代码、复杂度超标函数、过长函数、缺失类型注解、硬编码值
- 重构操作：提取共享函数、删除死代码、重命名、拆分函数、补充类型

## 提交规范

- Commit message 前缀：`[EVOLUTION]`
- 格式：`[EVOLUTION] feat: description` 或 `[EVOLUTION] refactor: description`
- 禁止修改 `.claude/`、`docs/` 目录结构

## 经验沉淀规则

- 每个 Agent 经验档案最多保留 50 条历史提案
- 超过 50 条时，最早的条目归档到 `experience/archive/`
- 每周日生成 `experience/weekly-summary.md`
- 每 10 次功能进化生成跨 Agent 横向对比总结

## 失败处理规则

- 可恢复错误：自动修复最多 2 轮
- 完全阻塞：连续 2 次失败后暂停，通知用户
- 超时：单阶段最多 30 分钟，超时保存进度并退出
